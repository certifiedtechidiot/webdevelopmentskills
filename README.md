## ⚖️ Conflict Resolution Hierarchy

When two or more frameworks offer differing directives for the same decision, the agent resolves them using this strict precedence order:

1. **1st Priority — Impeccable (Craft & Accessibility Floor)**: WCAG AA contrast (`4.5:1`), complete 6-state component coverage (*Default, Hover, Active, Focus, Disabled, Loading*), and visible `:focus-visible` rings. Craft floor cannot be bypassed for speed.
2. **2nd Priority — Hallmark (Anti-AI-Slop & Token Discipline)**: Zero untokenized hex colors, zero purple-blue gradients, zero nested cards, zero fake metrics. All styles must pass through `:root`.
3. **3rd Priority — AI Design Skill (Conversion & Layout Grid)**: One Offer → One Audience → One Primary Action. The 4px/8px layout grid and type scale govern rhythm.
4. **4th Priority — Taste Skill 2.5 (Screen Rhythm & Visual Realism)**: Single viewport hero (`1280x800` / `1440x900` desktop baseline), real product UI graphics, quiet micro-animations.
5. **5th Priority — OpenDesign (Brand Design System)**: Exact tokens, typefaces, elevation shadows, and border radii matching the selected brand blueprint (e.g. Stripe, Linear, Vercel).
6. **6th Priority — GSD (Velocity & Execution Loop)**: Engineering execution speed operates under the constraints established by the five pillars above.

## ⚡ Activation Tiers

To prevent unnecessary overhead on small tasks, the agent classifies every request into one of three activation tiers:

| Tier | Scope | Active Pillars | Overhead & Memory |
| :--- | :--- | :--- | :--- |
| **Tier 1 — Component** | Single isolated element (button, input, badge, dropdown) | Hallmark + relevant Impeccable playbook | **Zero overhead**: Skips `.planning/` memory and full page linter run. |
| **Tier 2 — Feature / Section** | A page section, modal, or multi-component flow (hero, pricing table, navigation bar) | Hallmark + AI Design + Taste 2.5 + Impeccable | **Lightweight**: Skips GSD project memory unless `.planning/` already exists in workspace. |
| **Tier 3 — Full Build / Redesign** | Complete website, full page, dashboard app, or end-to-end audit | All 6 Pillars | **Comprehensive**: Initializes `.planning/` memory, executes milestone loop, and runs full `sloplint.mjs` verification. |

Every AI response begins with an explicit tier declaration:
```text
Tier 2 activated — Feature build (hero + CTA section). GSD memory skipped (no .planning/ detected).
```

## 🔍 Verification Scripts & Lint Rules

The skill includes a standalone, zero-dependency Node.js verification suite (`Node >= 18`). See [**scripts/README.md**](scripts/README.md) for full documentation.

### Running Audits Manually
```bash
# Run anti-slop linter against HTML, CSS, JSX, or TSX files
node scripts/sloplint.mjs src/index.html src/styles.css

# Run cross-file design token consistency check
node scripts/consistency.mjs --dir=src
```

### Core Lint Rules Enforced by `sloplint.mjs`:
- **Stamp Enforcement**: First non-empty line of CSS must contain the Hallmark stamp.
- **Gradient Discipline**: Forbids generic purple-to-blue gradients (`#6366f1` to `#a855f7`).
- **Motion Accessibility**: Requires explicit `@media (prefers-reduced-motion: reduce)` block whenever animations or transitions are present.
- **Specific Transitions**: Forbids `transition: all`. Transitions must explicitly list animated properties.
- **Single-Viewport Hero**: Enforces `100dvh` / `100svh` and flags heros sized in raw `vh`.
- **Typographic Scale**: Enforces negative tracking on display headers and `text-wrap: balance`.
- **WCAG AA Contrast**: Enforces minimum `4.5:1` contrast ratio for all normal text.

## 📦 Installation & Verification

### 1. Antigravity (IDE & Desktop App 2.0)

**Global Installation (All Workspaces):**
Clone into your user profile skills directory:
```bash
git clone https://github.com/certifiedtechidiot/webdevelopmentskills.git ~/.gemini/antigravity/skills/webdevelopment
```

Ensure your `~/.gemini/config/skills.json` uses absolute paths:
```json
{
  "entries": [
    {
      "path": "C:/Users/<your-username>/.gemini/antigravity/skills"
    },
    {
      "path": "C:/Users/<your-username>/.gemini/config/skills"
    }
  ]
}
```

> [!TIP]
> **Windows Note**: Antigravity's Go runtime requires absolute drive paths (`C:/Users/...`) in `skills.json` and `plugins.json`. Do not use `~` paths on Windows.
>
> If Antigravity was already running when you installed the skill, reload the window (`Ctrl+R` or restart the app) so the UI's cached slash command dropdown refreshes.

**Project Workspace Installation:**

## 🛠️ Troubleshooting

### Issue: Typing `/web` does not show `/webdevelopment` in the autocomplete menu
1. **Window Cache**: Antigravity caches slash commands upon initial load. Reload the Electron window via `Ctrl+R` or restart the application.
2. **Path Resolution on Windows**: Verify `~/.gemini/config/skills.json` uses absolute paths (`C:/Users/...`) rather than tilde (`~/`). Check `language_server.log` for any `Failed to resolve absolute path` warnings.
3. **Workspace Override**: If your workspace has a local `.agent/skills/webdevelopment`, it will take precedence over the global skill.
